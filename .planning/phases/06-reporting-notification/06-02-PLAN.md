## Summary

Implement a `Notifier` abstract base class with three concrete implementations (Console, Slack, Email) that deliver build summary notifications to humans via multiple channels; ensure all notification failures are caught and logged so they never crash the pipeline.

---

## Requirements

**Primary Requirements (Must Fully Address):**
- **NOTIF-01** — Console notification always outputs build summary to stdout
- **NOTIF-02** — Slack notification via `MCT_SLACK_WEBHOOK_URL` using urllib (no external dependencies)
- **NOTIF-03** — Email notification via SMTP (`MCT_SMTP_*` env vars, uses `smtplib` stdlib)
- **NOTIF-04** — Notification failures are logged, never crash the pipeline

**Related Orchestrator Requirement:**
- **PIPE-04** — Notify stage always runs regardless of earlier failures

---

## Success Criteria

1. **Console Notifier:** Prints build summary (from `PipelineResult.to_summary_md()`) to stdout; always enabled; completes in <1 second
2. **Slack Notifier:** POSTs markdown summary to webhook URL (if `MCT_SLACK_WEBHOOK_URL` set); handles network errors gracefully; completes in <5 seconds
3. **Email Notifier:** Sends summary as email subject + body (if `MCT_SMTP_HOST` set); handles SMTP auth/connection errors; completes in <10 seconds
4. **Failure Resilience:** When Slack/email notifiers encounter errors, they log (at ERROR level) but return normally; pipeline continues unaffected
5. **Selective Activation:** Console always sends; Slack only if webhook URL configured; Email only if SMTP host configured
6. **No External Dependencies:** All code uses stdlib only (urllib, smtplib, json, logging)

   Define the `Notifier` ABC (abstract base class) that all notification implementations inherit from. Specify the contract: a `notify()` method that accepts a `PipelineResult` and sends notifications. Use frozen dataclass for any configuration.
   
   **Signature:**
   ```python
   from abc import ABC, abstractmethod
   
   @dataclass(frozen=True)
   class NotifierConfig:
       """Configuration for notifiers (pulled from env vars)."""
       slack_webhook_url: str = ""
       smtp_host: str = ""
       smtp_port: int = 587
       smtp_user: str = ""
       smtp_password: str = ""
       email_to: str = ""
   
   class Notifier(ABC):
       """Abstract base class for build result notifiers."""
       
       @abstractmethod
       def notify(self, result: PipelineResult) -> None:
           """Send notification about pipeline result.
           
           Args:
               result: The completed pipeline result to notify about.
           
           Raises:
               Nothing — all errors logged but not raised.
           """
           pass
   ```

2. **Implement `ConsoleNotifier` class in `multi_ci_tools/notifiers.py`**

   ```python
   class ConsoleNotifier(Notifier):
       """Prints build summary to stdout."""
   ```

3. **Implement `SlackNotifier` class using urllib**
   
   Implement Slack integration using stdlib `urllib` and `json`. POST the build summary to a webhook URL as a Slack message block. Handle network timeouts, HTTP errors, and JSON serialization errors gracefully.
   
   **Signature:**
   ```python
   class SlackNotifier(Notifier):
       """Posts build summary to Slack webhook."""
       
       def __init__(self, webhook_url: str) -> None:
           """Initialize with Slack webhook URL."""
           if not webhook_url:
               raise ValueError("Slack webhook URL is required")
           self.webhook_url = webhook_url
       
       def notify(self, result: PipelineResult) -> None:
           """POST markdown summary to Slack webhook."""
   ```
   
   **Implementation Details:**
   - Import: `urllib.request`, `urllib.error`, `json`
   - Webhook payload format (Slack markdown blocks):
     ```json
     {
       "blocks": [
         {
           "type": "section",
           "text": {
             "type": "mrkdwn",
             "text": "<markdown_summary>"
           }
         }
       ]
     }
     ```
   - HTTP POST timeout: 5 seconds (configurable, not env var)
   - Headers: `Content-Type: application/json`
   - Success: HTTP 200
   - Failures to handle:
     - Connection timeout → log error, return
     - Connection refused → log error, return
     - HTTP 4xx/5xx → log error with status code, return
     - JSON encoding error → log error, return
   
   **Error Handling:**
   ```python
   try:
       req = urllib.request.Request(
           self.webhook_url,
           data=json.dumps(payload).encode(),
           headers={"Content-Type": "application/json"}
       )
       with urllib.request.urlopen(req, timeout=5) as response:
           if response.status != 200:
               logger.error(f"Slack webhook returned {response.status}")
   except urllib.error.URLError as e:
       logger.error(f"Slack notification failed: {e}")
   except json.JSONDecodeError as e:
       logger.error(f"Failed to encode Slack message: {e}")
   except Exception as e:
       logger.error(f"Unexpected error sending Slack notification: {e}")
   ```
   
   **File:** `multi_ci_tools/notifiers.py:85-170`

4. **Implement `EmailNotifier` class using smtplib**
   
   Implement email delivery using stdlib `smtplib` and `email.mime`. Send the build summary as the email body. Support TLS on port 587 (STARTTLS). Handle authentication failures, SMTP connection errors, and malformed email addresses gracefully.
   
   **Signature:**
   ```python
   class EmailNotifier(Notifier):
       """Sends build summary via email."""
       
       def __init__(
           self,
           smtp_host: str,
           smtp_port: int,
           smtp_user: str,
           smtp_password: str,
           email_to: str,
       ) -> None:
           """Initialize with SMTP configuration."""
           if not all([smtp_host, email_to]):
               raise ValueError("SMTP_HOST and EMAIL_TO are required")
           self.smtp_host = smtp_host
           self.smtp_port = smtp_port
           self.smtp_user = smtp_user
           self.smtp_password = smtp_password
           self.email_to = email_to
       
       def notify(self, result: PipelineResult) -> None:
           """Send markdown summary email."""
   ```
   
   **Implementation Details:**
   - Imports: `smtplib`, `email.mime.text.MIMEText`, `email.mime.multipart.MIMEMultipart`
   - Subject: `"Build Notification: {job_name} — {status_emoji} {status}"`
   - Body: `result.to_summary_md()` (markdown formatted)
   - Content-Type: `text/plain` (or `text/html` if converted)
   - From: `smtp_user` (or default to `noreply@{hostname}`)
   - To: `email_to` (can be comma-separated)
   - SMTP Protocol:
     1. Connect to `smtp_host:smtp_port`
     2. Send STARTTLS (TLS handshake)
     3. Authenticate with `smtp_user` + `smtp_password`
     4. Send email
     5. Quit
   - Timeout: 10 seconds
   - Failures to handle:
     - Connection timeout → log error, return
     - Auth failure (401/535) → log error, return
     - DNS resolution failure → log error, return
     - Invalid email address → log error, return
     - SMTP protocol error → log error, return
   
   **Error Handling:**
   ```python
   try:
       with smtplib.SMTP(self.smtp_host, self.smtp_port, timeout=10) as server:
           server.starttls()
           server.login(self.smtp_user, self.smtp_password)
           server.send_message(msg)
           logger.info("Email notification sent successfully")
   except smtplib.SMTPAuthenticationError as e:
       logger.error(f"SMTP authentication failed: {e}")
   except smtplib.SMTPException as e:
       logger.error(f"SMTP error: {e}")
   except TimeoutError:
       logger.error(f"SMTP connection timeout to {self.smtp_host}:{self.smtp_port}")
   except OSError as e:
       logger.error(f"SMTP connection failed: {e}")
   except Exception as e:
       logger.error(f"Unexpected error sending email: {e}")
   ```

**Sequence for Each Notifier:**
1. Check if configured (env var present + non-empty)
2. Instantiate notifier
3. Call `notify(pipeline_result)`
4. If error occurs, log it and move to next notifier
5. Never raise exception (caught and logged)

## Error Handling

**No Notification Shall Ever Crash the Pipeline**

| Scenario | Behavior |
|----------|----------|
| Console notifier crashes | Log error, return from NOTIFY stage normally |
| Slack network timeout | Log: `"Slack webhook timeout after 5s"` → Continue to next notifier |
| Slack webhook returns 400 | Log: `"Slack webhook returned 400 Bad Request"` → Continue |
| Slack webhook DNS fails | Log: `"Slack webhook DNS resolution failed"` → Continue |
| SMTP connection timeout | Log: `"SMTP connect timeout to {host}:{port}"` → Continue |
| SMTP auth fails | Log: `"SMTP bad credentials for user {user}"` → Continue |
| SMTP server error (5xx) | Log: `"SMTP server error: {detail}"` → Continue |
| Email address invalid | Log: `"Invalid email recipient: {addr}"` → Continue |
| JSON encoding fails | Log: `"Failed to encode Slack message"` → Continue |
| All notifiers fail | Log warnings for each, pipeline still returns success |

**Logging Levels:**
- **INFO** — Notifier started, notification sent successfully
- **WARNING** — Notifier disabled due to misconfiguration (e.g., webhook URL empty)
- **ERROR** — Notifier encountered transient failure (network, auth, timeout) but didn't crash

**Code Pattern (Wrapper):**
```python
try:
    # attempt to send notification
except SpecificException as e:
    logger.error(f"Specific error: {e}")
    # intentionally don't re-raise
except Exception as e:
    logger.error(f"Unexpected error: {e}")
    # catch-all fallback
# Always continue to next notifier
```

## Configuration

**Environment Variables (All Optional Except Where Noted):**

| Variable | Type | Default | Required? | Example | Purpose |
|----------|------|---------|-----------|---------|---------|
| `MCT_SLACK_WEBHOOK_URL` | string URL | "" (disabled) | No | `https://hooks.slack.com/services/T...` | Slack webhook endpoint |
| `MCT_SMTP_HOST` | hostname | "" (disabled) | No (but required for email) | `smtp.gmail.com` | Email SMTP server |
| `MCT_SMTP_PORT` | int | 587 | No | `587`, `465`, `25` | SMTP server port (587=STARTTLS) |
| `MCT_SMTP_USER` | string | "" | No (required if SMTP_HOST set) | `ci-notifier@example.com` | SMTP login username |
| `MCT_SMTP_PASSWORD` | string | "" | No (required if SMTP_HOST set) | `${SMTP_PASSWORD_SECRET}` | SMTP login password (use CI secret) |
| `MCT_EMAIL_TO` | comma-sep string | "" | No (required if SMTP_HOST set) | `team@example.com` or `a@ex.com,b@ex.com` | Email recipient(s) |

**Activation Logic:**

- **Console notifier** — Always enabled (no env vars needed)
- **Slack notifier** — Enabled if `MCT_SLACK_WEBHOOK_URL` set and non-empty
- **Email notifier** — Enabled if both `MCT_SMTP_HOST` and `MCT_EMAIL_TO` set and non-empty

**Missing Configuration Handling:**

```
Scenario: MCT_SMTP_HOST=smtp.gmail.com but MCT_EMAIL_TO empty
Result: Log warning "Email notifier requires MCT_EMAIL_TO; skipping"
        Pipeline continues with Console + Slack notifiers only

Scenario: MCT_SLACK_WEBHOOK_URL set but malformed (not https://hooks.slack.com/...)
Result: Log warning "Invalid Slack webhook URL format; skipping"
        Pipeline continues with Console (+ Email if configured)

Scenario: No notifier env vars set
Result: Only ConsoleNotifier runs (always enabled)
```

## Implementation Notes

1. **No External Dependencies:** All imports from stdlib only (urllib, smtplib, json, logging, email.mime)
2. **Graceful Degradation:** Each notifier failure must be independent; failure of one never affects others
3. **Logging:** Use `logger.info()` for normal flow, `logger.warning()` for misconfiguration, `logger.error()` for runtime failures
4. **Thread Safety:** Not required (notifiers run sequentially in NOTIFY stage)
5. **Performance:** Target <2 seconds for console, <5 seconds for Slack, <10 seconds for email (total <15s)
6. **Markdown Format:** Leverage existing `PipelineResult.to_summary_md()` method for consistent formatting
7. **Email Content-Type:** Use `text/plain` for compatibility (no HTML rendering needed)
8. **Slack Markdown:** Use Slack's `mrkdwn` block type to render markdown within Slack UI
