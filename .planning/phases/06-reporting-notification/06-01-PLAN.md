## Summary

Implement XML parsers for Maven JUnit test reports and Checkstyle linting results, then integrate their output into the pipeline summary generation so test/lint counts appear in both `ci-result.json` and `summary.md` artifacts.

- **RPT-03** — Handle malformed XML gracefully (log warning, return zeros, don't crash)

## Success Criteria

1. **JUnit Parser:** Extracts `<testcase>` elements from surefire XML; counts tests as passed/failed/skipped; returns accurate totals even with missing `<testsuite>` attributes
2. **Checkstyle Parser:** Reads `<error>` elements from checkstyle XML; tallies severity levels (ERROR/WARNING/INFO)
3. **Malformed XML:** Encounters malformed surefire/checkstyle XML → logs warning → returns all-zeros counts → pipeline continues
4. **Integration:** Summary generation includes test counts and lint violations in markdown output
5. **No Crashes:** Parsers never crash the pipeline; errors are logged but handled gracefully
6. **Accurate Totals:** Manual verification: Run `mvn clean test checkstyle:check` on test Maven project → verify counts in summary match actual test output

## Tasks

1. **Create `multi_ci_tools/reporting.py` module with `JUnitParser` class**
   
   Implement `JUnitParser` using stdlib `xml.etree.ElementTree` to parse surefire test reports. The parser must extract `<testcase>` elements from all XML files in `target/surefire-reports/`, classify each as passed/failed/skipped, and return a dataclass result (total, passed, failed, skipped counts). Handle missing files (no tests run), empty `<testsuite>` elements, and malformed XML by catching `xml.etree.ElementTree.ParseError` and logging a warning with zeros.
   
   **Signature:**
   ```python
   @dataclass(frozen=True)
   class TestSummary:
       total: int
       passed: int
       failed: int
       skipped: int
   
   class JUnitParser:
       def parse(self, surefire_dir: str) -> TestSummary:
           """Parse surefire reports from directory; return test counts."""
   ```
   
   **File:** `multi_ci_tools/reporting.py:1-100`

7. **Add comprehensive error handling to parsers**
   
   Ensure both `JUnitParser.parse()` and `CheckstyleParser.parse()` catch and handle:
   - `FileNotFoundError` — Report file doesn't exist (return zeros, log info)
   - `xml.etree.ElementTree.ParseError` — Malformed XML (return zeros, log warning)
   - `PermissionError` — Can't read file (return zeros, log error)
   - `IOError` — Disk I/O failure (return zeros, log error)
   
   **Pattern:**
   ```python
   def parse(self, path: str) -> LintSummary:
       try:
           tree = ET.parse(path)
           # extract counts
           return LintSummary(...)
       except FileNotFoundError:
           logger.info(f"Checkstyle report not found: {path}")
           return LintSummary(0, 0, 0, 0)
       except ET.ParseError as e:
           logger.warning(f"Malformed checkstyle XML {path}: {e}")
           return LintSummary(0, 0, 0, 0)
       except (PermissionError, IOError) as e:
           logger.error(f"Error reading {path}: {e}")
           return LintSummary(0, 0, 0, 0)
   ```
   
   **File:** `multi_ci_tools/reporting.py:30-80, 130-160`

8. **Handle edge cases in JUnit parser**
   
   Address common JUnit XML variations:
   - **Empty `<testcase>` elements** — No child elements; status determined by presence of `<failure>`, `<error>`, `<skipped>` children
   - **Missing `<testsuite>` wrapper** — Some test frameworks emit only `<testcase>` elements; flatten them
   - **Multiple surefire report files** — Aggregate counts across all `*.xml` files in directory
   - **Tests without status attributes** — Assume passed if no failure/error/skipped child present
   
   **File:** `multi_ci_tools/reporting.py:50-95`

9. **Handle edge cases in Checkstyle parser**
   
   Address common Checkstyle XML variations:
   - **Missing severity attribute** — Default to ERROR
   - **Severity values:** ERROR, WARNING, INFO (case-insensitive; normalize to uppercase)
   - **Multiple files in report** — Aggregate violations across all `<file>` elements
   - **File with no violations** — Empty `<checkstyle>` root; return zeros
   
   **File:** `multi_ci_tools/reporting.py:145-175`

## Error Handling

**Parser Errors Are Graceful:**

| Scenario | Behavior |
|----------|----------|
| Surefire report missing | Log: `"Surefire report not found, skipping test parsing"` → Return `TestSummary(0,0,0,0)` |
| Surefire XML malformed | Log: `"Malformed surefire XML: {error details}"` → Return `TestSummary(0,0,0,0)` |
| Checkstyle report missing | Log: `"Checkstyle report not found, skipping lint parsing"` → Return `LintSummary(0,0,0,0)` |
| Checkstyle XML malformed | Log: `"Malformed checkstyle XML: {error details}"` → Return `LintSummary(0,0,0,0)` |
| File permission denied | Log: `"Unable to read {path}: Permission denied"` → Return zeros |
| Disk I/O error | Log: `"Error reading {path}: {IOError}"` → Return zeros |
| XML element parsing fails | Each element parsed independently; if one fails, continue with others |

**Pipeline Behavior:**
- Parser errors never raise exceptions (caught and logged)
- Pipeline continues regardless of parse failures
- `ci-result.json` and `summary.md` are always created (with zero counts if parsing failed)
- No test or lint summaries = omitted from JSON output (fields remain `None`)

## Implementation Notes

1. **XML Parsing Library:** Use stdlib `xml.etree.ElementTree` (imported as `ET`); no external dependencies
2. **Logging:** All parsers log at INFO (missing files), WARNING (malformed XML), ERROR (IO errors)
3. **Path Handling:** Use `os.path.join()` for cross-platform compatibility
4. **Thread Safety:** Not required (parsers run sequentially after stages complete)
5. **Performance:** XML parsing should complete in <100ms even for large test suites (1000+ tests)
6. **Workspace Context:** Assume `config.workspace` is always set and valid (validated in earlier phases)
