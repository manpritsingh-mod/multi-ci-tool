## Summary

Implement a thin Jenkinsfile wrapper that invokes the Python SDK inside a Docker container, reads the resulting `ci-result.json`, maps build status to Jenkins states (`unstable()` for warnings, `FAILURE` for failures), and archives artifacts. Also implement the `doctor` CLI command to validate workspace prerequisites (Java, Maven, Python, directory structure).

## Success Criteria

1. **Jenkinsfile execution:** `python -m multi_ci_tools run` runs inside Docker without network issues; produces `ci-result.json` in workspace
2. **Result parsing:** Jenkinsfile reads JSON successfully; extracts `overall` field (pass/warn/fail)
3. **Status mapping:** `overall: "warn"` → calls `unstable()`; `overall: "fail"` → sets `currentBuild.result = 'FAILURE'`
4. **Artifact archival:** `ci-result.json` and `summary.md` both archived; accessible in Jenkins UI
5. **JUnit publishing:** Jenkinsfile publishes test results from XML files via `junit` step
6. **Doctor command validation:** `python -m multi_ci_tools doctor` checks Java 11+, Maven 3.6+, Python 3.10+, src/pom.xml exist
7. **Doctor exit codes:** Healthy workspace → exit 0; issues found → exit 1 with clear messages
8. **Error handling:** Missing `ci-result.json` or malformed JSON → Jenkinsfile fails explicitly with diagnostic message
9. **No external dependencies:** Jenkinsfile uses only Groovy stdlib + Jenkins DSL; doctor uses only Python stdlib

## Tasks

1. **Create `Jenkinsfile` at project root with Docker agent**
   
   Implement a Declarative Pipeline that specifies a Docker agent with Maven + Java + Python pre-installed. The Docker image should be a well-known Java image (e.g., `maven:3.9-eclipse-temurin-21`). Use `agent { docker { image '...' } }` or `image.inside()` pattern to run all steps inside the container.
   
   **Jenkinsfile structure:**
   ```groovy
   pipeline {
       agent {
           docker {
               image 'maven:3.9-eclipse-temurin-21'
               args '-v /var/run/docker.sock:/var/run/docker.sock'
           }
       }
       stages {
           stage('Run Multi-CI-Tools') {
               steps {
                   sh 'python -m multi_ci_tools run --emit-json ci-result.json --emit-summary summary.md'
               }
           }
           stage('Parse Results') {
               steps {
                   sh 'cat ci-result.json'
               }
           }
       }
       post {
           always {
               archiveArtifacts artifacts: 'ci-result.json,summary.md', allowEmptyArchive: true
               junit testResults: 'target/surefire-reports/*.xml', allowEmptyResults: true
           }
       }
   }
   ```
   
   **File:** `Jenkinsfile` (root of project)

2. **Parse `ci-result.json` and map `overall` field to Jenkins build status**
   
   In the `post` block or a dedicated stage, read the JSON file and extract the `overall` field. Based on its value:
   - `overall: "pass"` → no action (success)
   - `overall: "warn"` → call `unstable()`
   - `overall: "fail"` → set `currentBuild.result = 'FAILURE'`
   
   Use Groovy JSON parsing (stdlib):
   ```groovy
   def parseResult(jsonPath) {
       def json = readJSON file: jsonPath
       echo "Pipeline result: ${json.overall}"
       if (json.overall == 'warn') {
           unstable('Build completed with warnings')
       } else if (json.overall == 'fail') {
           currentBuild.result = 'FAILURE'
       }
   }
   ```
   
   **File:** `Jenkinsfile:30-50`

3. **Add error handling for missing or malformed `ci-result.json`**

   ```groovy
   if (!fileExists('ci-result.json')) {

   try {
   ```

5. **Implement `doctor` CLI command in `multi_ci_tools/cli.py` or `__main__.py`**
   
   Create a new CLI subcommand that validates the workspace for required tools and structure. Implement using argparse (existing pattern in cli.py). The command should:
   - Check Java version (11 or higher) via `java -version`
   - Check Maven installation (3.6 or higher) via `mvn -v`
   - Check Python version (3.10 or higher) via `sys.version_info`
   - Check workspace structure (presence of `src/` and `pom.xml`)
   - Return exit code 0 if all checks pass, 1 if any check fails
   
   **Signature:**
   ```python
   def cmd_doctor(config: RunConfig) -> int:
       """Validate workspace and prerequisites."""
       checks = [
           check_java_version(),
           check_maven_installation(),
           check_python_version(),
           check_workspace_structure(config.workspace),
       ]
       passed = sum(1 for check in checks if check['status'] == 'pass')
       total = len(checks)
       logger.info(f"Doctor: {passed}/{total} checks passed")
       return 0 if all(c['status'] == 'pass' for c in checks) else 1
   ```
   
   **File:** `multi_ci_tools/cli.py:200-250`

6. **Implement `check_java_version()` function**
   
   Execute `java -version` (stderr output), parse version string, extract major version number, and verify it's 11 or higher. Log results at INFO level.
   
   ```python
   def check_java_version() -> dict[str, str | bool]:
       """Check if Java 11+ is installed."""
       try:
           result = subprocess.run(['java', '-version'], 
                                 capture_output=True, text=True, timeout=5)
           # Parse "openjdk version "21.0.2" 2024-01-16" → extract 21
           import re
           match = re.search(r'version "(\d+)', result.stderr + result.stdout)
           if not match:
               return {'name': 'Java', 'status': 'fail', 'reason': 'Cannot parse version'}
           version = int(match.group(1))
           if version >= 11:
               return {'name': 'Java', 'status': 'pass', 'version': str(version)}
           else:
               return {'name': 'Java', 'status': 'fail', 'reason': f'Found {version}, need 11+'}
       except FileNotFoundError:
           return {'name': 'Java', 'status': 'fail', 'reason': 'java command not found'}
       except Exception as e:
           return {'name': 'Java', 'status': 'fail', 'reason': str(e)}
   ```
   
   **File:** `multi_ci_tools/cli.py:250-280`

7. **Implement `check_maven_installation()` function**
   
   Execute `mvn -v`, parse version, and verify 3.6 or higher. Log results.
   
   ```python
   def check_maven_installation() -> dict[str, str | bool]:
       """Check if Maven 3.6+ is installed."""
       try:
           result = subprocess.run(['mvn', '-v'], 
                                 capture_output=True, text=True, timeout=5)
           # Parse "Apache Maven 3.9.6 (..." → extract 3.9
           import re
           match = re.search(r'Maven (\d+)\.(\d+)', result.stdout)
           if not match:
               return {'name': 'Maven', 'status': 'fail', 'reason': 'Cannot parse version'}
           major, minor = int(match.group(1)), int(match.group(2))
           if (major, minor) >= (3, 6):
               return {'name': 'Maven', 'status': 'pass', 'version': f'{major}.{minor}'}
           else:
               return {'name': 'Maven', 'status': 'fail', 'reason': f'Found {major}.{minor}, need 3.6+'}
       except FileNotFoundError:
           return {'name': 'Maven', 'status': 'fail', 'reason': 'mvn command not found'}
       except Exception as e:
           return {'name': 'Maven', 'status': 'fail', 'reason': str(e)}
   ```
   
   **File:** `multi_ci_tools/cli.py:280-310`

9. **Implement `check_workspace_structure()` function**

   ```python
   def check_workspace_structure(workspace: str) -> dict[str, str | bool]:
       """Check if workspace has Maven structure (pom.xml + src/)."""
       issues = []
       if not os.path.exists(os.path.join(workspace, 'pom.xml')):
           issues.append('pom.xml not found')
       if not os.path.exists(os.path.join(workspace, 'src')):
           issues.append('src/ directory not found')
       
       if issues:
           return {'name': 'Workspace structure', 'status': 'fail', 
                   'reason': '; '.join(issues)}
       return {'name': 'Workspace structure', 'status': 'pass'}
   ```
   
   **File:** `multi_ci_tools/cli.py:325-340`

## Error Handling

**Jenkinsfile Errors:**

| Scenario | Behavior |
|----------|----------|
| Docker image pull fails | Jenkins build fails immediately (Docker agent boot failure) |
| `python -m multi_ci_tools run` exits non-zero | Orchestrator failure handled; output in Jenkins console |
| `ci-result.json` not found in workspace | Jenkinsfile post block detects missing file → `currentBuild.result = 'FAILURE'` with diagnostic message |
| JSON parsing fails (malformed JSON) | Groovy JSON parser throws → Jenkinsfile catches → build marked `FAILURE` with error details |
| Artifact archival fails | Jenkins `archiveArtifacts` step fails → build marked `FAILURE` (Jenkins default behavior) |
| JUnit publishing finds no XML files | `junit` step succeeds with zero tests → no test record created (expected) |

**Doctor Command Errors:**

| Scenario | Behavior |
|----------|----------|
| Java not installed | Return `{'Java': 'fail', 'reason': 'java command not found'}` → exit 1 |
| Maven too old (2.x) | Return `{'Maven': 'fail', 'reason': 'Found 2.2.1, need 3.6+'}` → exit 1 |
| Python < 3.10 | Return `{'Python': 'fail', 'reason': 'Found 3.9, need 3.10+'}` → exit 1 |
| Workspace missing pom.xml | Return `{'Workspace': 'fail', 'reason': 'pom.xml not found'}` → exit 1 |
| Multiple failures | Return all failures; exit 1 on first failure (or log all and exit 1) |
| Command timeout (e.g., java -version hangs) | Catch timeout exception → return fail with reason → exit 1 |

**Pipeline/Orchestrator Errors (Handled by Phase 5+):**

These are already handled by the SDK and reflected in `ci-result.json`:
- Build command timeout → `stages[].status = "fail"`
- Test failure → `stages[].status = "fail"`, test summary populated
- Lint violation → `stages[].status = "warn"` or `"fail"` depending on `--strict`

## Implementation Notes

1. **Jenkinsfile language:** Declarative Pipeline (preferred) or Scripted (if needed for complex JSON parsing)
2. **JSON parsing in Groovy:** Use built-in `readJSON file: 'path'` (available in Jenkins DSL)
3. **Doctor subprocess execution:** Use `subprocess.run(timeout=5)` to prevent hanging
4. **Version parsing:** Use regex for robust version extraction (handles variations like "21.0.2", "1.8.0_372", "3.9.6")
5. **Error messages:** Clear and actionable (e.g., "Found Java 8, but 11+ required" not "Check failed")
6. **Exit codes:** Conventionally 0 = success, non-zero = failure (returned to shell)
