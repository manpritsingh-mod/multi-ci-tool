## Tasks

1. **Create `.github/workflows/ci.yml` with matrix strategy**
   
   Implement a GitHub Actions workflow with matrix strategy for Java and Python versions. Use `setup-java` and `setup-python` actions to prepare the environment. The matrix should test multiple combinations (e.g., Java 11/17/21 × Python 3.10/3.11/3.12) or a reduced set for faster feedback.
   
   **Workflow structure:**
   ```yaml
   name: CI
   
   on:
     push:
       branches: [main, develop]
     pull_request:
       branches: [main]
   
   jobs:
     build:
       runs-on: ubuntu-latest
       strategy:
         matrix:
           java-version: ['11', '17', '21']
           python-version: ['3.10', '3.11', '3.12']
         fail-fast: false
       steps:
         - uses: actions/checkout@v4
         - name: Set up Java
           uses: actions/setup-java@v3
           with:
             java-version: ${{ matrix.java-version }}
             distribution: 'temurin'
         - name: Set up Python
           uses: actions/setup-python@v4
           with:
             python-version: ${{ matrix.python-version }}
   ```
   
   **File:** `.github/workflows/ci.yml` (root of project)

3. **Parse `ci-result.json` and write GITHUB_STEP_SUMMARY**
   
   After SDK completes, read the JSON result, format a readable summary, and append to GITHUB_STEP_SUMMARY. The summary should include:
   - Overall build status (PASS/WARN/FAIL)
   - Stage results table
   - Test counts (if available)
   - Lint violation count (if available)
   - Execution duration
   
   ```yaml
   - name: Generate Step Summary
     if: always()
     run: |
       python << 'EOF'
       import json
       with open('ci-result.json') as f:
           result = json.load(f)
       summary = f"""
       # Multi-CI-Tools Pipeline Result
       
       **Status:** {result['overall'].upper()}
       **Duration:** {result['duration_seconds']:.1f}s
       
       ## Stages
       """
       for stage in result['stages']:
           summary += f"\n- **{stage['name']}:** {stage['status']}"
       
       with open(os.environ['GITHUB_STEP_SUMMARY'], 'a') as f:
           f.write(summary)
       EOF
   ```
   
   **File:** `.github/workflows/ci.yml:46-75`

4. **Handle SDK failures and set workflow outcome appropriately**
   
   The workflow should continue even if `python -m multi_ci_tools run` exits non-zero (using `continue-on-error: true` or explicit error handling). Then, based on `ci-result.json`, set the appropriate workflow conclusion:
   - `overall: "pass"` → workflow succeeds
   - `overall: "warn"` → workflow succeeds but with notice
   - `overall: "fail"` → workflow fails
   
   ```yaml
   - name: Determine Build Status
     if: always()
     run: |
       python << 'EOF'
       import json
       import sys
       with open('ci-result.json') as f:
           result = json.load(f)
       if result['overall'] == 'fail':
           sys.exit(1)
       elif result['overall'] == 'warn':
           print("::warning::Build completed with warnings")
       EOF
   ```
   
   **File:** `.github/workflows/ci.yml:76-90`

6. **Implement `dry-run` CLI command in `multi_ci_tools/cli.py`**
   
   Create a new CLI subcommand that prints the planned pipeline stages in order, respecting `--skip-stage` and `--stage` flags, without executing any commands. The output should be informational and human-readable.
   
   **Signature:**
   ```python
   def cmd_dry_run(config: RunConfig) -> int:
       """Show planned stages without executing them."""
       stages = [
           StageName.PREFLIGHT,
           StageName.RESOLVE_DEPS,
           StageName.LINT,
           StageName.BUILD,
           StageName.UNIT_TEST,
           StageName.SMOKE_TEST,
           StageName.PUBLISH,
           StageName.NOTIFY,
       ]
       
       # Apply --stage filter
       if config.stage:
           stages = [s for s in stages if s.value == config.stage]
       
       # Apply --skip-stage filter
       if config.skip_stages:
           stages = [s for s in stages if s not in config.skip_stages]
       
       print("Multi-CI-Tools Dry-Run")
       print(f"Workspace: {config.workspace}")
       print(f"Planned stages ({len(stages)} total):")
       for idx, stage in enumerate(stages, 1):
           print(f"  {idx}. {stage.value}")
       
       return 0
   ```
   
   **File:** `multi_ci_tools/cli.py:350-380`

9. **Implement stage filtering logic**
   
   In dry-run (and also in orchestrator for Phase 5+ consistency), apply the stage filters:
   - If `--stage <name>` is specified, only include that stage
   - If `--skip-stage <name>` is specified (can be repeated), exclude those stages
   - Default: all stages except NOTIFY (which always runs) and PUBLISH (which always runs)
   
   ```python
   def filter_stages(all_stages: list[StageName], 
                     stage_filter: str | None,
                     skip_stages: list[str]) -> list[StageName]:
       """Apply --stage and --skip-stage filters."""
       if stage_filter:
           # Only include the specified stage
           return [s for s in all_stages if s.value == stage_filter]
       
       # Exclude skip_stages
       return [s for s in all_stages if s.value not in skip_stages]
   ```
   
   **File:** `multi_ci_tools/cli.py:380-395`

## Error Handling

**GitHub Actions Workflow Errors:**

| Scenario | Behavior |
|----------|----------|
| `setup-java` fails | Step fails → workflow marked red; subsequent steps skipped |
| `setup-python` fails | Step fails → workflow marked red; subsequent steps skipped |
| `python -m multi_ci_tools run` exits non-zero | Step fails but workflow continues (due to `continue-on-error: true` or error handling); parse result |
| `ci-result.json` not found | `Generate Step Summary` step fails but workflow continues; final status determined by explicit error check |
| JSON parsing fails in Python script | Exit code 1 → workflow marked red |
| GITHUB_STEP_SUMMARY write permission denied | Script fails → workflow marked red (unlikely in GitHub Actions environment) |
| Artifact upload fails | Upload step fails → workflow marked red (artifacts unavailable) |

**Dry-Run Command Errors:**

| Scenario | Behavior |
|----------|----------|
| Adapter detection fails (no CI env vars) | Fallback to LocalAdapter; print "Detected: Local" |
| Invalid `--stage` name | argparse validation fails → print usage → exit 1 |
| Invalid `--skip-stage` name | argparse validation fails → print usage → exit 1 |
| Workspace doesn't exist | Print warning, continue (infrastructure check skipped) |
| No stages match filter | Print "0 stages planned"; exit 0 (valid, informational) |

**Pipeline/Orchestrator Errors (Handled by Phase 5+):**

These are already handled by the SDK and reflected in `ci-result.json`:
- Build timeout → `stages[].status = "fail"`
- Test failure → `stages[].status = "fail"`, test summary populated
- Lint violation → `stages[].status = "warn"` or `"fail"` depending on `--strict`

## Implementation Notes

1. **Workflow YAML format:** Use GitHub Actions syntax; indent with 2 spaces
2. **Matrix strategy:** `fail-fast: false` ensures all combinations run even if one fails
3. **Step summary:** Append to `$GITHUB_STEP_SUMMARY` file (provided by GitHub Actions)
4. **Build status in workflow:** Use `exit` command to set final job status (0 = success, 1 = failure)
5. **Artifact naming:** Include matrix variables in artifact name for uniqueness (e.g., `build-artifacts-java11-py310`)
6. **Dry-run stage order:** Match orchestrator stage order: preflight → resolve_deps → lint → build → unit_test → smoke_test → publish → notify
7. **Dry-run exit code:** Always 0 unless there's a usage error (argparse validation)
8. **Error messages:** Clear guidance on what to do (not just what failed)
